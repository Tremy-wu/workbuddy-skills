# 100 条工作提效 Prompts 结构拆解与可复用范式

> 数据源：`staruhub/awesome-workbuddy` → `prompts/100-work-efficiency-prompts.json`（本地克隆于 `2026-08-03-awesome-workbuddy/`）
> 分析日期：2026-08-03｜方法：全量 100 条结构解析 + 正则信号量化（非抽样）

## 一、数据形态（确定）

- 顶层为 **JSON 数组，长度 100**，无外层包装。
- 每条记录固定 **7 字段**，缺失率 0%：`id` / `title` / `category` / `scene` / `prompt` / `expected_output` / `tip`。
- `id` 严格 1–100 连续且唯一（已校验）。
- `category` 共 **10 类，每类恰好 10 条**（均衡设计，非自然分布）：
  `deep-research` / `data-analysis` / `doc-writing` / `ppt` / `meeting` / `email-calendar` / `project-mgmt` / `dev` / `growth` / `admin-hr-finance`。
- 字段长度（字符）：`prompt` 137–200（中位 189，强约束）；`expected_output` 13–30；`tip` 14–27。

## 二、可复用结构信号（量化，N=100）

| 结构信号 | 出现频次 | 解读 |
|---|---|---|
| 显式指定输出格式（.md/.xlsx/表/图） | **84%** | 绝大多数 prompt 把"交付物长什么样"写死 |
| 指定角色/身份（我是/作为/我们） | 37% | 约 1/3 做角色代入 |
| 量化指标/标准（%、个、项、KPI） | 34% | 1/3 内置可验收标准 |
| 步骤/分点要求 | 30% | 近 1/3 要求分步或顺序 |
| 约束/边界声明（不要/仅/区分） | 29% | 近 1/3 显式划边界 |
| 联网/检索指令 | 22% | 调研类才要求 |
| 交叉验证/来源引用 | 22% | 同上，仅调研类高频 |
| 字数/篇幅约束 | 19% | 少数但关键（控制幻觉） |
| 角色代入场景（给客户/向老板汇报） | 11% | 低频，靠 scene 字段补足 |

`scene` 字段：**59/100** 采用「角色 / 场景」斜杠结构（如 `咨询顾问 / 项目启动前摸底`），把"谁、在什么时机用"外挂为元数据，与 prompt 正文解耦。

`expected_output` 高频交付物标记：`.md` 48、`.xlsx` 31、`清单` 16、`报告` 15、`PPT` 12、`方案` 7、`邮件` 6。

## 三、提炼的 5 个可复用提示词范式

**范式 1 — 场景锚定（Scene Anchoring）**
把"使用者身份 + 触发时机"前置，要么进 prompt 正文（37%），要么进 `scene` 元数据（59%）。经验推论：带场景的 prompt 比纯任务句更不易跑偏。
> 句式：`[我是/我们] + [角色] + [在什么节点/为什么做] + [任务]`

**范式 2 — 交付物显式化（Explicit Deliverable）**
84% 的 prompt 直接点名输出格式与产物类型。这是"可验收"的关键。
> 句式：`输出一份[格式]：[产物1] + [产物2] + [清单/表]`
> 例：`输出一份5000字以内的结构化报告（.md）：市场规模及测算逻辑、产业链图谱、前五名企业市占率表 + 引用清单`

**范式 3 — 可验证约束（Verifiable Constraint）**
把"怎么算做对"写进指令：交叉验证（22%）、量化标准（34%）、篇幅上限（19%）、边界声明（29%）。
> 句式：`至少交叉验证[ N ]个独立信息源，区分事实与推测` / `验证标准：[指标]下降[ N ]%`

**范式 4 — 篇幅纪律（Length Discipline）**
`prompt` 正文 137–200 字、中位 189，信息密度极高、无客套。范式：一条 prompt 只解决一个明确任务，不堆"未来可能用到"的背景。

**范式 5 — 技巧外挂（Tip Decoupling）**
每条 prompt 配独立 `tip`（14–27 字）存放"如何让它更准"的提示，与指令正文分离。范式：指令负责"做什么"，tip 负责"怎么调参"，二者解耦便于复用与 A/B。

## 四、通用模板（可直接套用）

```
[身份/场景铺垫] + [具体任务] + [输出格式与交付物] + [验证/约束标准] + （可选）[联网检索]
```
- 元数据层：`category`（10 选 1）+ `scene`（角色 / 时机）独立存储
- 提示层：`tip` 独立字段，不放进 prompt 正文

## 五、对本机 6994 个技能编写的启示

1. **SKILL.md 复用"场景锚定"**：`description` 字段必须含"触发场景 + 匹配关键词"，对照范式 1，避免无标注技能（全局规范 §8.3 已要求，此处用数据佐证其必要性）。
2. **技能产出复用"交付物显式化"**：技能说明里写清"调用后交付什么文件/结果"，而非泛泛"帮你做事"。
3. **技能校验复用"可验证约束"**：把质量门禁（见 `skill-quality-gate/`）的通过标准写成可量化项，对应范式 3。
4. **技能描述复用"篇幅纪律"**：`description` 一行说清，不写散文。
